1 · The Locked Spec (what we are building)

Cognitive job: Given two or more already-running agents whose declared resource claims, heartbeats, and checkpoint declarations conflict, mechanically detect the conflict, compute what intervention is structurally permitted given only the corroboration behind each fact and the freshness of each agent's own safe-stop declaration, and rule on the strongest intervention both permitted and warranted by severity — always citing the conflict id, the rule, and the evidence, and never granting an intervention more forceful than the offending agent's own corroborated, checkpointed evidence can actually support. See .genesis/PLAN.md §1–2 for the full claim and closed vocabulary.

Inputs: typed ResourceClaim[], Heartbeat[], and CheckpointDeclarations, each carrying a Corroboration level (self-reported | cross-checked | independently-verified) — never a bare trust boolean.  →  Outputs: a closed Intervention (observe · warn · pause · halt [checkpointed | forced] · quarantine), always paired with the conflict it rules on and the evidence that justified it.

Autonomy level: Fully autonomous for detecting conflicts, computing what's structurally permitted, and ruling up to and including quarantine — none of that needs a human in the loop. What is deliberately NOT autonomous: halt/forced, the only variant that cannot compile without a per-conflict HumanAuthorization. No engine milestone may construct that variant on its own initiative.

Failure tolerance: Fail toward the weakest defensible intervention, never toward a fabricated stronger one. A corrupting-severity conflict the gate only permits warn for must return warn plus an explicit escalationRecommended: true — never a silently invented quarantine, and never a bare warn that reads as "handled." Silence from an agent is never evidence of safety; a held claim stays held, never released, once its owner stops heartbeating.

Filled during Genesis (G0–G2, .genesis/PLAN.md), following the shape used in decision-engine's, shadow-run's, and memory-ledger's own .genesis/DONE.html (this project's infrastructure siblings) — content is project-specific, structure only is borrowed. No engine code exists yet: M1 (contracts) is a separate milestone with its own PR and its own verifier.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

Dependency direction inward, zero cycles: lib/contracts → lib/conflict → lib/gate → lib/arbitrate, one-directional (modular-architecture gate)
npm run typecheck clean AND npm test green
One verify pass by a separate agent/model (L4)
No milestone's freeze boundary touched by a later milestone (freeze-boundary gate — the independent verifier's first job on every milestone)
A halt/forced literal missing authorizedBy or conflictId must not compile; a source-scan test proves "forced" never appears in lib/gate/**'s non-test source (no-self-authorized-force gate, from M1/M4)
Intervention is exhaustively matched via an assertNeverIntervention helper, proven live by adding a 6th variant and confirming every call site fails to compile (exhaustiveness-is-live gate, from M1)
detectConflicts is proven order-independent across every permutation of a claim set, and rejects a hostile (throwing-getter/Proxy) claims array as a typed failure, never an uncaught exception (pure-and-hostile-input gate, from M3)
quarantine never appears in the gate's available set when every claim's corroboration is self-reported; arbitration falls back to warn and says plainly that isolation could not be enforced (no-fabricated-quarantine gate, from M4/M5)
A corrupting-severity conflict the gate only permits a weaker intervention for returns that weaker intervention plus escalationRecommended: true — never a silent downgrade reported as adequate (honest-ceiling gate, from M5/M7)
The failure suite's ten cases each assert a specific typed result, not merely "no exception thrown," including the disclosed, unsolved priority-inversion case (failure-suite gate, from M7)
The live demo URL injects a colliding remediation claim and produces the same ruling as npm run demo:incident's own fixture, checked by an independent verifier comparing outputs directly (deliverable gate — the brief requires a live demo)
A clean clone plus npm ci plus typecheck plus test passes with no credentials configured (clean-clone gate)

A milestone is DONE only when every applicable box above is checked by the verifier, and never by the building agent marking its own work. This genesis repo has no engine code yet — every gate above becomes checkable starting with M1's own PR and its own verifier.
